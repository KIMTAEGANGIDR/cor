# ADR-002: 파싱 전략 결정

> **상태**: 초안 (실제 데이터 확인 후 확정 필요)
> **날짜**: 2025-01-21
> **결정자**: 프로젝트 담당자

## 컨텍스트

OCR로 추출한 텍스트를 구조화된 법령 데이터로 변환하는 파싱 전략이 필요함.

### 최종 목표

**100%에 근접하는 정확도 + 국제 규격 XML (Akoma Ntoso) 변환**

- 조문 단위 정확한 파싱 (BAB/Pasal/Ayat/Huruf/Angka)
- Akoma Ntoso 3.0 XML 표준 준수
- 휴먼 검토 프로세스를 통한 품질 보장
- 법적 인용 가능한 수준의 정확도

## 결정

### 1. 파싱 파이프라인 (자동 + LLM 검증 + 휴먼)

```
[Raw OCR Text]
      ↓
Phase 1: 전처리 (노이즈 제거)
      ↓
Phase 2: 구조 추출 (연도별 파서)
      ↓
Phase 3: LLM 자동 검증 (기계적 + 의미론적)
      ↓
  ┌───┴───┐
  │       │
 Pass    Flag
  ↓       ↓
샘플링   휴먼 검토
(대학원생) (대학생→대학원생→변호사)
  │       │
  └───┬───┘
      ↓
Phase 4: Akoma Ntoso XML 변환
      ↓
[최종 산출물] → 100% 정확한 XML
```

### 2. 전처리가 핵심

노이즈 제거가 잘 되면 파싱은 상대적으로 쉬워짐:

- 워터마크 제거 (`www.djpp.depkumham.go.id` 등)
- 페이지 헤더/푸터 제거 (`PRESIDEN REPUBLIK INDONESIA`)
- OCR 오류 수정 (`2OO9` → `2009`, `Pasa1` → `Pasal`)
- 줄바꿈 정규화 (단어 중간 줄바꿈 병합)

### 3. 연도별 파서 분리

인도네시아 법령은 연도별로 포맷이 다름:

| 연도 | 특징 | 우선순위 |
|------|------|----------|
| 2020+ | 비교적 일관, SK No 포함 | **1순위** |
| 2000-2019 | 스캔+OCR, 페이지 헤더 혼입 | 2순위 |
| 1970-1999 | 과도기, "Menetapkan:" 등장 | 3순위 |
| ~1969 | 네덜란드어 혼용, 불규칙 | 4순위 (휴먼 비중 높음) |

**모든 연도 대상** - 레거시 문서도 스킵하지 않음

### 4. LLM 기반 검증 시스템

#### 왜 LLM인가?

기존 접근법의 문제:
```
사람 A가 검수 → "문제 없음" → 통과
                    ↓
             실제로는 오류 있음
                    ↓
             영원히 묻힘
```

**사람이 못 찾으면 아무도 못 찾는 구조** → 100% 정확도 불가능

#### LLM 검증 (전수 검사)

```
[OCR 텍스트] + [파싱 결과]
         ↓
┌────────────────────────────────┐
│      LLM 자동 검증              │
│                                │
│  1. 기계적 비교                 │
│     - 글자/단어 수 일치         │
│     - 누락 텍스트 검출          │
│     - Pasal 번호 연속성         │
│     - 구조 완전성               │
│                                │
│  2. 의미론적 비교               │
│     - "파싱이 원본을 반영하나?" │
│     - 문맥상 이상한 부분        │
│     - 잘린 문장, 뒤섞인 순서    │
│     - 참조 관계 정합성          │
└────────────────────────────────┘
         ↓
    Pass / Flag
```

#### 장점

| 기존 (사람 중심) | 개선 (LLM + 사람) |
|------------------|-------------------|
| 사람 2명이 전수 검사 | LLM이 전수 검사 |
| 사람이 놓치면 끝 | LLM이 1차 필터 |
| 비용 높음 | 사람은 플래그된 것만 |
| 일관성 낮음 | LLM은 일관적 |

### 5. 휴먼 검토 프로세스 (3단계 피라미드)

```
LLM Flag → L1: 대학생 (다수)
              - OCR 오류 수정
              - 기본 구조 확인
              - 불확실 → L2로 에스컬레이션
                    ↓
           L2: 대학원생 (중간)
              - 복잡한 구조 파싱
              - L1 작업 샘플링 검증
              - 법적 해석 필요 → L3로
                    ↓
           L3: 변호사 (소수)
              - 법적 해석 최종 판단
              - L2 작업 샘플링 검증
              - 규칙 예외 결정
```

**LLM Pass 문서**: 대학원생이 샘플링 검증 (LLM 신뢰도 모니터링)

### 6. 품질 목표

| 단계 | 목표 |
|------|------|
| 자동 파싱 | 구조 추출 완료 |
| LLM 검증 | 전수 검사, Pass/Flag 분류 |
| 휴먼 리뷰 | Flag 문서 100% 검토 |
| 샘플링 검증 | Pass 문서 신뢰도 확인 |
| 최종 XML | Akoma Ntoso 3.0 **100% 정확** |

## 참고: 현재 파서의 한계

현재 `StructureParser`는 단순 정규식 기반:

```python
BAB_PATTERN = r'BAB\s+([IVXLCDM]+)\.?\s*\n\s*(.+?)(?=\n|Pasal)'
PASAL_PATTERN = r'Pasal\s+(\d+)\s*\.?\s*\n(.*?)(?=Pasal\s+\d+|BAB|...)'
```

한계점:
- 전처리 없이 바로 구조 추출 시도
- 연도별/포맷별 변화 미대응
- OCR 노이즈 처리 없음
- 검증 로직 없음
