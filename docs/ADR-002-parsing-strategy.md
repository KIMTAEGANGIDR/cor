# ADR-002: 파싱 전략 결정

> **상태**: 초안 (실제 데이터 확인 후 확정 필요)
> **날짜**: 2025-01-21
> **결정자**: 프로젝트 담당자

## 컨텍스트

OCR로 추출한 텍스트를 구조화된 법령 데이터로 변환하는 파싱 전략이 필요함.

### 목표 정확도

**조문 단위 인용 가능** (Level 2)

| Level | 용도 | 요구사항 |
|-------|------|----------|
| 1 | 검색용 | 전문 검색으로 커버, 파싱 정확도 낮아도 됨 |
| **2** | **조문 단위 인용** | **Pasal/Ayat 경계 정확해야 함** |
| 3 | 법률 분석/비교 | 높은 정확도 + 관계 추출 필요 |

## 결정

### 1. 파싱 파이프라인 3단계

```
[Raw OCR Text]
      ↓
Phase 1: 전처리 (노이즈 제거)
      ↓
Phase 2: 구조 추출 (연도별 파서)
      ↓
Phase 3: 검증 (신뢰도 점수)
      ↓
[Structured Document] + [신뢰도 플래그]
```

### 2. 전처리가 핵심 (80%)

노이즈 제거가 잘 되면 파싱은 상대적으로 쉬워짐:

- 워터마크 제거 (`www.djpp.depkumham.go.id` 등)
- 페이지 헤더/푸터 제거 (`PRESIDEN REPUBLIK INDONESIA`)
- OCR 오류 수정 (`2OO9` → `2009`, `Pasa1` → `Pasal`)
- 줄바꿈 정규화 (단어 중간 줄바꿈 병합)

### 3. 연도별 파서 분리

인도네시아 법령은 연도별로 포맷이 다름:

| 연도 | 특징 | 우선순위 |
|------|------|----------|
| 2020+ | 비교적 일관, SK No 포함 | **1순위** |
| 2000-2019 | 스캔+OCR, 페이지 헤더 혼입 | 2순위 |
| 1970-1999 | 과도기, "Menetapkan:" 등장 | 3순위 |
| ~1969 | 네덜란드어 혼용, 불규칙 | 최후순위 (스킵 가능) |

### 4. 검증 로직 필수

- Pasal 번호 연속성 체크
- 필수 요소 존재 확인 (제목, Pasal 1)
- 신뢰도 점수 산출
- 낮은 신뢰도 문서 플래그

### 5. 100% 정확도는 목표가 아님

- 80-90% 정확도 목표
- 파싱 실패 문서는 원본 텍스트로 검색 가능
- 레거시 문서(~1969)는 노력 대비 효용 낮음

## 참고: 현재 파서의 한계

현재 `StructureParser`는 단순 정규식 기반:

```python
BAB_PATTERN = r'BAB\s+([IVXLCDM]+)\.?\s*\n\s*(.+?)(?=\n|Pasal)'
PASAL_PATTERN = r'Pasal\s+(\d+)\s*\.?\s*\n(.*?)(?=Pasal\s+\d+|BAB|...)'
```

한계점:
- 전처리 없이 바로 구조 추출 시도
- 연도별/포맷별 변화 미대응
- OCR 노이즈 처리 없음
- 검증 로직 없음
