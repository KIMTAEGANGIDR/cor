## 1. 파이프라인 개요

### 1.1 공식 파이프라인 (2026-01-24 채택)

```
PDF → Surya OCR → 규칙 교정 → 품질 검증
                                 ↓
               ┌─────────────────┴─────────────────┐
               │                                   │
         ≥95% PASS                           <95%
         (자동 승인)                              ↓
                             ┌───────────────────┴───────────────┐
                             │                                   │
                      90-95% WARNING                       <90% FAIL
                             ↓                                   │
                      최대 5회 재처리 (300 DPI)                  │
                             ↓                                   │
                      개선 안됨 ────────────────────────────────→│
                                                                 ↓
                                                          LLM 교정
                                                    (Claude Sonnet via OpenRouter)
                                                                 ↓
                                                   ┌─────────────┴─────────────┐
                                                   │                           │
                                             LLM 확신 ≥90%              LLM 애매함
                                             + 품질 ≥95%                     ↓
                                             (자동 승인)                 인간 검토
```

### 1.2 핵심 구성 요소

| 파일 | 역할 | 버전 |
|------|------|------|
| `surya_pipeline.py` | Surya OCR 래퍼, LAMPIRAN 제외 | v1.0 |
| `quality_validator.py` | 품질 검증, AutomatedPipeline | v1.0 |
| `llm_corrector.py` | OpenRouter → Claude Sonnet | v1.0 |
| `ocr_corrector.py` | 규칙 기반 교정 | v1.1 (옛 철자법 추가) |
| `indonesian_dict.py` | 인도네시아어 사전 + Sastrawi 스테머 | v1.0 |

### 1.3 품질 기준 (KOICA zero-defect)

| 등급 | 점수 | 조치 |
|------|------|------|
| **PASS** | ≥95% | 자동 승인 |
| **WARNING** | 90-95% | 최대 5회 재처리 |
| **FAIL** | <90% | LLM 교정 → 인간 검토 |

### 1.4 품질 점수 구성

```
종합 점수 = (OCR 신뢰도 × 0.45) + (사전 검증 × 0.35) + (법률 용어 × 0.15) + (구조 패턴 × 0.05)
```

## 3. 발견된 문제

### 3.1 옛 인도네시아어 철자법 (Ejaan Lama)

**영향 범위:** 1972년 이전 문서 (추정 수백 개)

**철자법 변천:**

| 시기 | 이름 | 특징 |
|------|------|------|
| ~1947 | Ejaan van Ophuijsen | oe→u (soedah→sudah) |
| 1947-1972 | Ejaan Republik (Ejaan Soewandi) | dj→j, tj→c, nj→ny, sj→sy, j→y |
| 1972~ | EYD (Ejaan Yang Disempurnakan) | 현대 철자법 |

**실제 예시 (1953년 문서):**

| 원본 (OCR) | 기대값 | 문제 |
|------------|--------|------|
| Djuli | Juli | ✅ 해결됨 |
| djumlah | jumlah | ✅ 해결됨 |
| wadjib | wajib | ✅ 해결됨 |
| Djenderal | Jenderal | ⚠️ "Yenderal"로 오변환됨 |
| perdjalanan | perjalanan | ✅ 해결됨 |

**문제점:**
- `j→y` 규칙이 `dj→j` 변환 후에도 적용되어 오변환 발생
- 단어 위치에 따른 `j` 처리 규칙 필요

### 3.2 OCR 노이즈

**유형:**

| 패턴 | 예시 | 원인 추정 |
|------|------|----------|
| 의미 없는 숫자 | `33.33` | 페이지 여백 인식 오류 |
| 통화 기호 조합 | `$200 $400 $` | 스캔 얼룩/잡음 |
| 특수문자 조합 | `±1,5°¥ +3 +3 °C` | 인쇄 불량/스캔 품질 |
| 외국어 혼입 | `più` (이탈리아어) | OCR 모델 오인식 |
| 반복 대시 | `-- -- -- --` | 테이블/구분선 오인식 |

**해결 시도:**
- 정규식 기반 노이즈 패턴 필터링 추가
- 일부 해결되었으나 완전하지 않음

### 3.3 HTML 태그 혼입

**문제:** OCR 결과에 `<br>`, `<b>`, `<i>` 등 HTML 태그 포함

**원인:** Surya OCR이 PDF 내 서식 정보를 HTML로 출력

**해결:** `_remove_html_tags()` 메서드 추가 → ✅ 해결됨

### 3.4 사전 검증 실패율

**문제:** 옛 철자법 단어가 현대 인도네시아어 사전에 없음

| 문서 | 사전 검증 실패율 | 원인 |
|------|-----------------|------|
| 1953년 | 24.8~28.5% | 옛 철자법 |
| 1998년 | 21.2% | 일부 고유명사/약어 |
| 2024년 | ~5% | 일반적 OCR 오류 |

**해결 시도:**
- 옛 철자법 → 현대 철자법 변환 후 검증
- 부분적 개선 (28.5% → 24.8%)

### 3.5 법률 구조 패턴 인식 실패

**문제:** 오래된 문서에서 법률 구조 패턴 0개로 감지됨

**원인 추정:**
- 1953년 문서 형식이 현대 법률 문서와 다름
- 패턴 정규식이 현대 형식에 최적화됨
- 옛 용어 사용: "Menimbang" vs "Membatja"

**현재 패턴 (현대 문서 기준):**

```python
STRUCTURE_PATTERNS = [
    r"(?i)^pasal\s+\d+",           # Pasal 1, Pasal 2, ...
    r"(?i)^\(\d+\)",               # (1), (2), ...
    r"(?i)^[a-z]\.",               # a., b., c., ...
    r"(?i)^bab\s+[ivxlcdm]+",      # BAB I, BAB II, ...
    r"(?i)^bagian\s+\w+",          # Bagian Kesatu, ...
    r"(?i)^ayat\s+\(\d+\)",        # Ayat (1), ...
]
```

### 3.6 LLM 교정 한계

**문제:**
1. JSON 파싱 오류 (1953년 문서)
2. 확신도 90% 미만 (88~92%)으로 자동 승인 안됨

**LLM 교정 결과:**

| 문서 | 수정 개수 | 확신도 | 결과 |
|------|----------|--------|------|
| 1953년 | 41개 | 92% | 품질 95% 미달 → 인간 검토 |
| 1998년 | 20개 | 88% | 확신도 미달 → 인간 검토 |

## 4. 시도한 해결책

### 4.1 옛 철자법 변환 규칙 (ocr_corrector.py v1.1)

**추가된 기능:**

```python
OLD_SPELLING_PATTERNS = [
    (r"tj", "c"),     # tjara → cara
    (r"dj", "j"),     # Djuli → Juli
    (r"nj", "ny"),    # njalah → nyalah
    (r"sj", "sy"),    # sjarat → syarat
    (r"ch", "kh"),    # chabar → khabar
    (r"(?<![dnt])j(?!u)", "y"),  # jang → yang
    (r"oe", "u"),     # soedah → sudah
]

OLD_SPELLING_WORDS = {
    "djuga": "juga",
    "wadjib": "wajib",
    "perdjalanan": "perjalanan",
    # ... 40+ 단어
}
```

**결과:**
- 대부분의 옛 철자법 변환 성공
- `j→y` 규칙 과적용 문제 발생

### 4.2 노이즈 필터링 (ocr_corrector.py v1.1)

**추가된 패턴:**

```python
NOISE_PATTERNS = [
    r"[\$\+\-\*\#\@\!\%\^\&\=]{2,}",
    r"[\°\±\×\÷\¥\€\£]{1,}",
    r"\d+\.\d+[\°\%]",
    r"più",
    r"[\.\-\=\_]{5,}",
    # ...
]
```

**결과:**
- 일부 노이즈 제거됨
- 모든 패턴 커버 불가

### 4.3 HTML 태그 제거 (ocr_corrector.py v1.1)

**추가된 기능:**

```python
HTML_TAG_PATTERN = re.compile(r"</?(?:br|p|div|span|b|i|u|strong|em)[^>]*>")
```

**결과:** ✅ 완전 해결
